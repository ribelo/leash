# Eta design audit for Leash — 2026-09-26

## Review verdicts (added after source verification)

The audit below was produced by a delegated worker and then checked claim by claim against the Eta sources by the coordinating session. Verdicts, in the audit's numbering; the corrections below take precedence over the original text where they differ.

What the audit did not look at, checked by the coordinator:

- **TLS to OpenRouter**: not a gap. `eta_http_eio` depends on `eta_http_tls_openssl` itself; Pie's `with-test` listing is only for the SHA-1 helper in its tests.
- **JSON at the boundaries**: Eta offers `Eta_ai.Json` (raw Yojson helpers) and `eta_schema` + `eta_schema_yojson` (checked decoding with JSON-pointer issue locations). Decision: control protocol and config through `eta_schema`; CDP messages raw Yojson. Recorded in the managed-Chrome spec.
- **Finalizers under cancellation**: `finally` and `acquire_release` run cleanup in a cancellation-protected frame, so `etaproc`'s SIGTERM → grace sleep → SIGKILL release can run under a cancelled parent. `uninterruptible`/`interruptible` exist for anything finer.
- **Process door and systemd**: `run_main` returns 130 on SIGTERM interruption; the unit needs `SuccessExitStatus=130` or a clean stop shows as failed. Recorded in the packaging spec.
- **Eio's SIGKILL-on-switch-end** (separate finding, same day): not a bug, a blunt design; the `etaproc` ticket now owns a private child switch so the SIGKILL is a backstop, never a race with the SIGTERM finalizer.

Scope: current local Eta and Pie checkouts, against Leash milestones 1–6.
This is a read-only source/interface audit, not a runtime proof or an Eta patch.
A ticket marked `ready-for-agent` is planned behavior, **not** a shipped API.

Classification: *missing API* is an unimplemented capability with a defined Eta ticket;
*bug* is behavior at odds with the exposed contract; *design worth improving* is
a contract or adoption pattern that complicates this consumer without being incorrect.

## Ranked findings

### 1. No scoped child with Chrome's fd 3/4 and graceful retirement — missing API, blocking

**Eta evidence.** [Eta_eio interface](../../../ocaml/Eta/lib/eio/eta_eio.mli#L224-L257) passes the Eio process manager into an
environment-aware main but exposes no process resource.
[Process ticket](../../../ocaml/Eta/docs/issues/process-scoped-child/01-process-scoped-child.md#L1-L31) is open
(`ready-for-agent`): it specifies extra fd mappings, typed exit, SIGTERM/grace/SIGKILL, awaited cleanup, optional restart events.
The existing [Activation.own](../../../ocaml/Eta/lib/component/eta_component.mli#L116-L139) tracks acquired resources but does not spawn children.
Leash's [managed-Chrome spec](../issues/managed-chrome/01-managed-chrome.md#L18-L33) needs this for milestone 1 `chrome-9ex7`,
`chrome-qo4q`, and orderly shutdown `chrome-b288`.
That spec explicitly records that Eio switch release SIGKILLs immediately ([line 66](../issues/managed-chrome/01-managed-chrome.md#L66)).
**Pie:** Its component adoption is historical, not proof of a process primitive; current [assistant ownership
decision](../../../pie/docs/issues/assistant-ownership/01-remove-shadow-component-orchestration.md#L13-L24) removed the graph. No
comparable Pie fd-3/4 child evidence.
**Recommendation:** land `etaproc` in Eta before Chrome implementation; distinguish clean voluntary exit from failed launch and
crash, make close await child and workers, preserve the primary failure plus cleanup causes. Do not implement an app-local Eio
switch shim.

### 2. No request/reply correlator on framed duplex stream — missing API, blocking

**Eta evidence.** [Stream.Source](../../../ocaml/Eta/lib/stream/eta_stream.mli#L212-L236) adapts queues and producers, not pending request slots.
[Correlator ticket](../../../ocaml/Eta/docs/issues/stream-rpc-correlator/01-stream-rpc-correlator.md#L8-L31) is open; requires
registration before write, typed send/closed/timeout results, cancellation cleanup, session+ID keys, and joining readers without
notification-consumer progress.
Leash milestone 1 `chrome-qnul`, `chrome-1yn9` and milestone 2 `tab-9x5e` need concurrent CDP replies and independent events
([spec](../issues/managed-chrome/01-managed-chrome.md#L21-L29), [wait story](../issues/tab-observation-and-actions/01-tab-observation-and-actions.md#L31-L33)).
**Pie:** no CDP-like correlation in the [current service](../../../pie/packages/pie/assistant/service.ml); the earlier component
graph is removed ([decision](../../../pie/docs/issues/assistant-ownership/01-remove-shadow-component-orchestration.md#L24-L30)).
**Recommendation:** land `etarpc` in Eta; transport framing and CDP JSON/session semantics stay in Leash. In particular test
cancellation vs reply vs EOF and no write retries after an uncertain dispatch.

### 3. No hardened, bounded Unix control listener — missing API, blocking

**Eta evidence.** [Listener ticket](../../../ocaml/Eta/docs/issues/ipc-control-listener/01-ipc-control-listener.md#L8-L34) is open
and owns private directory/socket verification, a live-listener-safe lock, peer bounds and deadlines.
Leash milestone 1 `chrome-fwnu` and `chrome-38a4` demand owner-only socket and safe malformed-request handling
([spec](../issues/managed-chrome/01-managed-chrome.md#L29-L32)); milestone 6 packages the same endpoint
([plan](../milestones.md#L8-L13)).
**Pie already hit it:** its [server](../../../pie/packages/pie/assistant_service/server.ml#L171-L269) implements directory checks,
lock identity, live-listener probe and a peer budget locally. [Leash ADR](../adr/0001-eta-first-platform.md#L7-L16) rejects a
third copy.
**Recommendation:** land `etaipc` in Eta; retain JSON command decoding and owner semantics in Leash. Probe active listeners
without unlinking; test non-socket path, insecure directory, saturated peers and stalled requests with real local socket fixtures.

### 4. One peer deadline conflates slowloris protection with long-running commands — design worth improving

**Eta evidence.** [etaipc's proposed contract](../../../ocaml/Eta/docs/issues/ipc-control-listener/01-ipc-control-listener.md#L26-L31)
sets a monotonic read-through-reply deadline for each admitted peer; the API is
not shipped, so this is a ticket-design conflict rather than an observed defect.
**Leash conflict:** [milestone 1's listener](../issues/managed-chrome/01-managed-chrome.md#L43-L44) says *one second for reading a request line*,
not for the entire navigation, which can take 30 seconds.
[Handoff](../issues/human-handoff/01-human-handoff.md#L18-L24) can wait 15 minutes,
and [drive](../issues/drive/01-drive.md#L18-L24) has a default 120-second deadline.
A global one-second read-through-reply budget cancels these valid requests;
a 15-minute global budget would leave slow clients consuming peer capacity.
**Pie:** [server budget](../../../pie/packages/pie/assistant_service/server.ml#L3-L7) defaults to one second;
that tiny service endpoint is not evidence that Leash's blocking handoff fits.
**Recommendation:** revise `etaipc` before implementation to enforce a short, byte-bounded
ingress/read budget independently of a bounded handler/reply budget supplied by
Leash per operation, or allow policy transfer after decoding under the same
peer-cap reservation. Define what happens if the peer disconnects mid-handoff.
Test slowloris expiry without aborting a legitimate long handoff; cite
`chrome-1yn9`, `hand-lmd5` and `drive-ix5t` at milestones 1, 4 and 5.

### 5. Component adoption can create a second, false service lifecycle — design worth improving in usage/docs, not an Eta defect

**Eta evidence.** [Context.run](../../../ocaml/Eta/lib/component/eta_component.mli#L626-L637) owns one lexical lifetime;
[admission semantics](../../../ocaml/Eta/lib/component/eta_component.mli#L683-L701) distinguish accepted work from caller
cancellation, and non-returning callbacks cannot be preempted.
[Activation.own](../../../ocaml/Eta/lib/component/eta_component.mli#L116-L139) owns cleanup but does not establish that the *real*
Chrome/control workers, rather than placeholders, are entries.
Milestone 1 `chrome-qo4q`/`chrome-6lfk` and milestone 6 `svc-gxhu` packaging require truthful status and stop; see [managed
Chrome](../issues/managed-chrome/01-managed-chrome.md#L26-L33) and [service packaging
spec](../issues/service-packaging/01-service-packaging.md).
**Pie hit this sharply:** [original adoption ADR](../../../pie/docs/adr/0001-adopt-eta-component.md#L1-L11) promised a tree;
[later decision](../../../pie/docs/issues/assistant-ownership/01-remove-shadow-component-orchestration.md#L13-L40) deleted 12
dummy graph modules, inert inputs and fabricated health, and removed `eta_component` from Pie. The archived [component
ticket](../../../pie/docs/issues/archive/component-runtime/01-component-runtime.md#L19-L29) is historical, not current dogfooding.
**Recommendation:** Leash uses one context only if each entry directly owns an actual process, listener or worker via
`Activation.own`, with diagnostics tied to actual running state. Add an Eta component guide/example showing concrete effect
ownership and accepted-fence settlement; do not treat a declarative tree as process supervision by itself. A smaller lexical owner
is preferable to a shadow graph.

### 6. Named background cancellation can become a false finalizer failure — bug

**Eta evidence.** [Effect.with_background](../../../ocaml/Eta/lib/eta/effect.mli.in#L745-L762) is the natural lexical owner for an
essential pipe reader; [background guide](../../../ocaml/Eta/docs/background-work.md#L3-L13) says it cancels and awaits the child
when the body completes.
Milestone 1 CDP reader `chrome-2z2z`/`chrome-6lfk` and milestone 2 event-driven wait `tab-9x5e` depend on clean cancellation
([stories](../issues/managed-chrome/01-managed-chrome.md#L27-L29), [wait](../issues/tab-observation-and-actions/01-tab-observation-and-actions.md#L32)).
**Pie reports it (not independently reproduced here):** [missing-Eta-API note](../../../pie/docs/missing-eta-api.md#L29-L37) reports that naming a reader can turn
internal cancellation into anonymous interruption and surface `Finalizer(Interrupt)` after successful body; its PulseAudio reader
deliberately remains unnamed ([callsite](../../../pie/packages/pie/pulse/client.ml#L454)). [Pie regression
tests](../../../pie/packages/pie/test/test_pie.ml#L4548-L4621) cover named background clean-cancel behavior; these do not negate
the production workaround without a demonstrated fix.
**Recommendation:** fix Eta's instrumentation to preserve cancellation identity through `named`; add regression under both runtime
and eta_test for named readers blocked on pipe/stream. Until verified, Leash can use unnamed `with_background` and put
human-readable names in outer spans/log context, recording a temporary `etagap-*` workaround.

### 7. System One client is not yet shipped; existing Chat reasoning controls are insufficient to claim explicit disable — missing API

**Eta evidence.** [OpenRouter interface](../../../ocaml/Eta/lib/ai/openrouter/eta_ai_openrouter.mli#L38-L41) has a reasoning
record with optional *effort*, not a boolean `enabled=false`; [Chat](../../../ocaml/Eta/lib/ai/openrouter/eta_ai_openrouter.mli#L74-L105)
exposes optional reasoning and Responses transport. Do not assume omission disables provider reasoning.
[System One ticket](../../../ocaml/Eta/docs/issues/ai-openrouter-systemone/01-ai-openrouter-systemone.md#L20-L47) is open;
requires typed questions/answers, structural fail-closed parsing, 4 MiB/1 MiB bounds, one total deadline and max two attempts.
Leash milestone 5 `drive-zml5` and `drive-ls3c` need JEV decisions and text help ([plan](../milestones.md#L12-L22), [drive
spec](../issues/drive/01-drive.md)).
**Pie:** Its [missing API note](../../../pie/docs/missing-eta-api.md#L7-L17) confirms Eta OpenRouter responses do not expose HTTP
response-idle policy; Pie wraps entire transcription in total `timeout_as`. Pie has no System One consumer
([ticket](../../../ocaml/Eta/docs/issues/ai-openrouter-systemone/01-ai-openrouter-systemone.md#L62-L66)).
**Recommendation:** land `etaso` as specified, separate from Chat, using injectable HTTP and clock. Explicitly verify the helper's
wire-level reasoning disable; if existing Chat cannot encode it, extend Eta's reasoning type to represent disabled rather than
appending unsafe raw JSON in Leash. Work around response-idle exposure with a finite operation timeout only if its broader
semantics are acceptable, and log `etagap-*`.

### 8. `Exit.render_error` hides composite causes — design worth improving

**Eta evidence.** [Exit.render_error](../../../ocaml/Eta/lib/eta/exit.mli#L53-L59) renders only a bare `Fail`; composites, defects
and interruption yield None even when a typed failure is nested. Meanwhile
[Effect.race](../../../ocaml/Eta/lib/eta/effect.mli.in#L210-L226) may return loser-finalizer diagnostics and
[finally](../../../ocaml/Eta/lib/eta/effect.mli.in#L607-L620) retains cleanup causes.
Leash milestone 1 `chrome-b288` and milestone 5 model failures, plus milestone 6 journal diagnostics, need a useful cause while
preserving redaction ([managed Chrome](../issues/managed-chrome/01-managed-chrome.md#L33), [plan](../milestones.md#L12-L13)).
**Pie hit it:** [process boundary](../../../pie/packages/pie/process.ml#L113-L118) calls `render_error`, risking a generic message
for composite failure; the production workaround is to inspect/format full Cause separately ([same
file](../../../pie/packages/pie/process.ml#L91-L100)).
**Recommendation:** Eta should offer a separate safe full-cause renderer or structured cause-to-diagnostic visitor, not silently
widen `render_error`'s deliberately narrow contract. Leash maps typed errors at protocol boundary but logs sanitized full cause
through `Cause.pp`, never raw request/page/model text.

### 9. Generic retry is unsuitable for browser actions — design worth improving in guidance, not bug

**Eta evidence.** [Effect.retry](../../../ocaml/Eta/lib/eta/effect.mli.in#L503-L518) retries typed failure by schedule;
[retry_or_else](../../../ocaml/Eta/lib/eta/effect.mli.in#L520-L539) also retries by typed cause and does not know whether remote
side effects occurred. [HTTP client](../../../ocaml/Eta/lib/http_eio/client.mli#L62-L68) exposes request_with_retry without CDP
action knowledge.
Leash milestone 2 `tab-bw4j`/`tab-p3x1`/`tab-9x5e` and milestone 5 drive must never repeat a dispatched action ([snapshot/action
stories](../issues/tab-observation-and-actions/01-tab-observation-and-actions.md#L24-L32), [safety
rule](../../AGENTS.md#L62-L65)).
**Pie:** no proof Pie encountered browser action retry; its [OpenRouter workaround](../../../pie/docs/missing-eta-api.md#L14-L17)
is timeout policy, not action retry.
**Recommendation:** no Eta behavior change; document an explicit idempotency boundary: schedule only Chrome launches, pre-dispatch
observations and System One's specified transport/429 policy. Leash never wraps click/fill/nav or CDP writes with generic retry;
timeout after dispatch is an uncertain outcome, not permission to resend.

### 10. A virtual Eta clock does not virtualize OS/HTTP/browser I/O — design worth improving in test guidance

**Eta evidence.** [eta_test.with_test_clock](../../../ocaml/Eta/lib/test/eta_test.mli#L78-L82) controls `delay`, `timeout`,
`repeat` and `retry` sleeps, while [Async.fork_run](../../../ocaml/Eta/lib/test/eta_test.mli#L94-L114) lets a test advance time
around a running effect. [Eta_eio.Runtime.create](../../../ocaml/Eta/lib/eio/eta_eio.mli#L105-L125) requires its sleep and now_ms
to share a monotonic base. This is not an OS process clock, Eio network poller or fake model server.
Milestone 1 `chrome-qo4q`, milestone 3 expiry, milestone 4 bounded handoff, milestone 5 model deadline all need deterministic time
([plan](../milestones.md#L8-L13)).
**Pie:** [speech deadlines requirement](../../../pie/docs/requirements/speech-operation-deadlines.md#L19-L23) similarly calls for
stalled local HTTP/WS fixtures plus controllable Eta clock, not clock alone.
**Recommendation:** keep policy under Eta Effect clock, inject scripted CDP framed messages and fake model HTTP client/server; use
real socket/process fixtures only for integration behavior. Do not promise virtual time for Eio kernel waits or SIGTERM delivery.
See detailed test matrix below.

## What is fine for this consumer

- [Promise](../../../ocaml/Eta/lib/eta/promise.mli#L1-L11) has one-shot retained Exit, waiter broadcast and cancellation cleanup:
good for CDP settlement *inside* the proposed correlator, not an excuse to recreate the registry in Leash.
- [Semaphore.with_permits](../../../ocaml/Eta/lib/eta/semaphore.mli#L49-L76) releases on cancellation and has an abort-aware
variant; one permit per tab fits `tab-hxld`. Create per-tab state in Leash, not in a global semaphore.
- [Queue](../../../ocaml/Eta/lib/eta/queue.mli#L1-L16) distinguishes graceful close and shutdown;
[Channel](../../../ocaml/Eta/lib/eta/channel.mli#L1-L15) provides bounded FIFO. Use bounded buffering/explicit overflow handling
for Chrome event traffic.
- [Eta_stream](../../../ocaml/Eta/lib/stream/eta_stream.mli#L229-L237) owns producer lifetime; its
[timeout](../../../ocaml/Eta/lib/stream/eta_stream.mli#L128-L137) is per pull, not necessarily a whole `wait` command deadline.
Frame NUL JSON in Leash; reuse the stream for transport once process adapters exist.
- [Effect.with_scope/acquire_release](../../../ocaml/Eta/lib/eta/effect.mli.in#L733-L741) and
[Activation.own](../../../ocaml/Eta/lib/component/eta_component.mli#L116-L139) already preserve owned finalizers. No replacement
scope system needed.
- [Observability Logger](../../../ocaml/Eta/lib/observability/logger.mli#L15-L22) has structured records and
[console_json](../../../ocaml/Eta/lib/observability/logger.mli#L71-L80) can write journal-captured stderr/stdout;
[eta_redacted](../../../ocaml/Eta/lib/redacted/eta_redacted.mli#L1-L13) hides values when its printer is used. Redaction is *not*
automatic for arbitrary log strings: Leash must never log raw CDP payloads/model state/keys.
- [HTTP Eio scoped client](../../../ocaml/Eta/lib/http_eio/client.mli#L50-L68) is appropriate as the System One/client adapter;
[OTLP scoped initialization](../../../ocaml/Eta/lib/otel_eio/eta_otel_eio.mli#L172-L208) keeps exporter lifetime explicit. Neither
requires rework for journal logging.

## Deterministic test story

| Leash seam / story | What is deterministic now | Remaining gap and practical fixture |
| --- | --- | --- |
| Control protocol, ownership `chrome-38a4`, `tab-hxld`, `own-uo77` | In-process Eta runtime and deterministic ordered request injection; controlled effects can stage races ([eta_test Controlled](../../../ocaml/Eta/lib/test/eta_test.mli#L117-L160)). | Actual socket permissions, liveness and peer bounds require a Unix socket fixture after `etaipc`; control JSON and owner logic remain Leash tests. |
| CDP message stream `chrome-2z2z`, `chrome-6lfk`, `tab-9x5e` | Scripted NUL-delimited JSON frames, out-of-order replies, notifications and EOF; advance virtual clock after pending request sleeps are registered. | Need `etarpc` to assert cancellation clears pending slot and reader joins; need `etaproc` for real fd-3/4 mapping, SIGTERM/grace and OS cleanup integration. |
| Timeouts and TTL `tab-9x5e`, milestone 3 expiry | [Effect.now_ms/sleep/timeout](../../../ocaml/Eta/lib/eta/effect.mli.in#L547-L583) and [Test_clock](../../../ocaml/Eta/lib/test/eta_test.mli#L9-L41) permit boundary checks just before/at/after expiry. | Use one monotonic clock for idle timestamps and sweep sleeps; test paused handoff and human-origin never-close; avoid wall time (`Test_unix_time` exists separately at [44–49](../../../ocaml/Eta/lib/test/eta_test.mli#L44-L49)). |
| Schedule-driven Chrome restart `chrome-qo4q`, `chrome-2z2z` | Fake process exit stream + Eta schedule and virtual sleep can assert delays, cap and generation invalidation. | `etaproc`'s optional supervised generation/event interface is not landed; Leash may own policy over scoped single-child primitive; real process signal timing needs integration tests. |
| Handoff `hand-lmd5` (milestone 4) | With injected focus/notify effects and clock, handoff deadline and ownership state are deterministic. | niri, notification action and desktop focus are external and need adapter/live checks. |
| Model clients `drive-ix5t` (milestone 5) | Local fake HTTP/client tests decode errors, cancellation and helper behavior; System One ticket explicitly requests clock/sleep and injectable client ([testing](../../../ocaml/Eta/docs/issues/ai-openrouter-systemone/01-ai-openrouter-systemone.md#L49-L55)). | Until `etaso` lands, no real client contract to test; for end-to-end socket/TLS/body stalls, fake server uses real I/O, so don't call those wall-clock-free. |
| Log/trace `svc-qilu` (milestone 6) | [eta_test log tracing](../../../ocaml/Eta/lib/test/eta_test.mli#L52-L92) captures attributes; assert secrets and page/model data absent. | Journal/OTLP pipeline is integration-only; test rendered cause plus redaction policy at application boundary. |

**Test method.** Run the same pure protocol/service effects under eta_test and Eta_eio without nested runtimes; fork the root
effect, wait for a known sleeper/pending call, advance `Test_clock`, then await its Exit. Assert no pending fibers and full cause,
not only a timely return ([Run expectations](../../../ocaml/Eta/lib/test/eta_test.mli#L272-L289)). Race selection is first
*success*, not first exit, so use `timeout_as` rather than ad-hoc `race` for deadlines ([race
contract](../../../ocaml/Eta/lib/eta/effect.mli.in#L210-L232)).

## Scope and evidence limits

The Leash milestone map is [milestones](../milestones.md#L6-L22); story identifiers above are stable IDs in the six [Leash
specs](../issues/managed-chrome/01-managed-chrome.md#L16-L33). IDs in the matrix refer to the precise Leash story lines linked in
their source specs.
Eta has four directly relevant open `ready-for-agent` tickets:
`etaproc`, `etarpc`, `etaipc`, `etaso`; also [remaining mode casts](../../../ocaml/Eta/docs/issues/remaining-mode-casts/01-prove-or-remove-remaining-mode-casts.md#L1-L20)
is open cross-cutting portability hardening, not a Leash milestone blocker. Other relevant historical bug tickets sampled in the
index have `completed` status; `superseded` is not OPEN.
Pie [REVIEW](../../../pie/REVIEW.md#L1-L14) describes legacy resource and typed-error pain; its own final [assistant ownership
decision](../../../pie/docs/issues/assistant-ownership/01-remove-shadow-component-orchestration.md#L22-L40) is stronger evidence
about actual component use than the adoption ADR. No compiler, Chrome or full-suite test was run: this report is an interface and
source audit.
