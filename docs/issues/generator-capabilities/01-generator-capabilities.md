# Give generators and tests explicit capabilities

## User Story

As a Leash maintainer, I want every generator and test to pass the capability
gate without allowances, so that build-time and test authority are explicit
too. ^gencaps-rh1m

## Acceptance Criteria

- Each generator declares `ox_caps` and `ox_caps.door` on its executable
  stanza and mints once through `Ox_caps_door.powerbox ()` at entry. The
  declared dependency authorizes the mint; no blessed path or suppression is
  required, and no `ox_app` dependency is added.
- File readers and directory walkers take only `Cap.fs_read`; emitting the
  skill data also takes `Cap.stdout`. The error-topic generator takes only
  `Cap.stdout`. All dangerous calls use the matching `Ox_caps.Cap_*` wrapper.
- The application entry uses `Ox_app.run_and_exit_with_args`; the Door owns
  process exit without changing exit codes, stderr or cleanup.
- Each capability-using test entry mints once through `Ox_test.powerbox ()`,
  authorized by its stanza declaring `ox_test`, without `ox_caps.door`.
  Tests and helpers accept explicit open rows containing only the capabilities
  they use or pass onward; dangerous calls use matching wrappers.
- The repository capability gate uses the engine's default scope, including
  the test tree, with no explicit path restriction or allow-list entries,
  and decides all typed modules without findings.
- `ox-val-behaviour` and `ox-cancel-safety` decide interface sentences against
  the implementation: a non-suspending claim reaches no Eio suspension point,
  documented raises agree with reachable raises, and documented cleanup runs
  on cancellation rather than only success. Unresolved callbacks, partial
  applications and returned closures are named undecided, not passed. Any
  correction changes the sentence, not implementation behaviour; an apparently
  wrong implementation is brought to the user instead.
- The default scan starts at the workspace root, including benchmarks, tools,
  scripts containing OCaml and generated OCaml under `_build`; generated-source
  findings identify the producing stanza.
- Deliberately violating fixtures, if needed, live in a nested Dune project with
  its own `dune-project`; an explicitly named path overrides every filter.
  No source fixture marker, allow-list entry or gate-specific exemption is used.
  Ordinary test helpers remain built and scanned.
- Test commands, output, exit codes and assertions remain unchanged.
- Generated bytes, traversal order, arguments and failures remain unchanged.
- The full repository build, test, formatting and capability gates pass.

## Scope

Capability plumbing, honest interface behaviour documentation and an updated Ox
dependency pin; generator paths and test assertions remain unchanged. The
separately authorized Ox API prerequisite bounds OTLP ending by five seconds,
replacing the previous unbounded shutdown drain. The live acceptance
executable is built and scanned, not run against Chrome by the default suites.
No Ox source changes or dependency installation.

### Separately authorized Ox API prerequisite

The initial build failed because [telemetry.ml](<../../../packages/leash/telemetry.ml>)
called `Ox_otel.create` without its newly mandatory `ending_budget`. The
coordinating session explicitly authorized `Ox.Duration.seconds 5`, following
Ox's own ordinary exporter-test convention. Leash previously supplied no OTLP
request deadline, so there was no repository deadline to reuse: the old
shutdown drain was effectively unbounded. This **changes shutdown behaviour**:
the first shutdown or owner release starts a single five-second budget covering
sealing, sends, recovery and control settlement; pending exports may be abandoned
when it expires instead of delaying shutdown indefinitely. Normal export
requests are unchanged. Leash has no direct `Client.body` extraction or
`Body_too_large` error arm, so neither HTTP API migration required consumer edits.
