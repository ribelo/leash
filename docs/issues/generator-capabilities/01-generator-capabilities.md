# Give generators explicit capabilities

## User Story

As a Leash maintainer, I want every generator to pass the capability gate
without allowances, so that build-time authority is explicit too. ^gencaps-rh1m

## Acceptance Criteria

- Each generator declares `ox_caps` and `ox_caps.door` on its executable
  stanza and mints once through `Ox_caps_door.powerbox ()` at entry. The
  declared dependency authorizes the mint; no blessed path or suppression is
  required, and no `ox_app` dependency is added.
- File readers and directory walkers take only `Cap.fs_read`; emitting the
  skill data also takes `Cap.stdout`. The error-topic generator takes only
  `Cap.stdout`. All dangerous calls use the matching `Ox_caps.Cap_*` wrapper.
- The application entry uses `Ox_app.run_and_exit_with_args`; the Door owns
  process exit without changing exit codes, stderr or cleanup.
- The repository capability gate has no allow-list entries and decides all
  typed modules without findings.
- Generated bytes, traversal order, arguments and failures remain unchanged.
- The full repository build, test, formatting and capability gates pass.

## Scope

Capability plumbing and an updated Ox dependency pin only; the generator
paths and application behavior remain unchanged. No Ox source changes.
