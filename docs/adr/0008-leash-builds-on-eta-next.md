# Leash builds on eta-next, and is its first consumer

Eta v1 (a blueprint interpreter over Eio) is being replaced by eta-next (direct style on Eio, `result` errors, one application model; see `/home/ribelo/projects/ribelo/ocaml/eta-next/docs/why-next.md`). Leash is greenfield and all operating-system seam — process supervision, pipes, a Unix socket, timers — which is exactly where v1's interpreter hurt most, so Leash becomes the first consumer of eta-next rather than the last consumer of v1. ADR-0001's rule stands with the branch changed: anything that is an effect-shaped resource or lifecycle concern without a browser concept is built in eta-next first, pulled by a Leash story ID. The six v1 tickets written for Leash (`etaproc`, `etarpc`, `etaipc`, `etadoor`, `etaor`, `etaso`) are superseded; their pure parts are copied when pulled. Milestone 1's specification is unchanged in behaviour and will be re-cut against eta-next's packages (`eta`, `eta_app`, a process resource, a Unix listener, a JSON codec) before implementation starts; the Leash flake will pin the eta-next worktree.
