# The map draws itself: playbooks compile from successful runs, and the site verifies them

**Automatic means verified, not blind — and verification has two forms, because not every mission can be run twice.** Ordering trousers, uploading a video, sending a message: a second run is a second order. So a compiled procedure is installed by whichever of two gates fits. **Gate A, replay:** for a mission the compiler judges repeatable (reads, searches, navigation, collection, adding to a cart that is not checked out), the runner tries the draft on the next matching mission and installs it if JEV chose it and its expectations passed. **Gate B, agreement:** for a mission that must not be repeated, the compiler installs the draft when `successes` independent traces (default 2) agree — the same page-kind path, the same operations on the same roles and labels, with only the typed arguments differing — and the planner, shown the agreement, confirms the generalization. Two humans doing the same thing the same way is evidence a map is right; it is the only evidence available when the thing cannot be done again. The compiler classifies the mission as repeatable or not from its page-kind path and operations (a submit on a payment, upload, or messaging page kind is non-repeatable; the operator may pin a site's kinds either way in the playbook) and records which gate installed each procedure in its provenance. Repair follows the same split: a repair of a non-repeatable procedure replaces the broken one by agreement of the repair with the failing trace's observed page, not by re-running the order. Rejected: installing on compile (a wrong generalization would cost every future mission on that site and nobody would notice, by design); requiring replay for everything (it would exclude exactly the missions that matter most); a nearest-case hint to JEV at run time (measured worse: more context lowers JEV's accuracy, 4/5 → 2/5); fine-tuning (JEV is fixed). `discover` is folded in: exploring is driving, and the draft appears on its own.

**Automatic means verified, not blind.** A compiled procedure is a *draft* until it has driven a mission successfully as a procedure — JEV choosing it, its expectations passing on the live site. In `auto`, the runner tries drafts on the next matching mission and installs the one that worked; a draft that fails is kept as evidence and retried after repair. When an installed procedure fails twice (the existing planner trigger), the planner's repair replaces it only after the repair succeeds. The gate is the site, not a human. Rejected: installing on compile (a wrong generalization would cost every future mission on that site and nobody would notice, by design); a nearest-case hint to JEV at run time (measured worse: more context lowers JEV's accuracy, 4/5 → 2/5); fine-tuning (JEV is fixed). `discover` is folded in: exploring is driving, and the draft appears on its own.

Consequences: traces persist under XDG state with bounded retention; page kinds are inferred on sites without a playbook so a trace has something to compile on; the planner gains a `continue` answer so Luna can hand control back to JEV after acting; `drive` is the command agents reach for, with a given tab kept and a created tab closed.

**Amendment, 2026-10-03 (operator).** Learned procedures may carry scripts the compiler writes. The earlier rule that no model-written JavaScript ever reaches the page is withdrawn for compiled playbooks: collection tasks ("every title and price in a category") need a script to read many records, and nobody else will write it — "Who is supposed to write the JavaScript? Definitely not a human." Safety moves from authorship to the gates: a compiled script is read-only by contract (it returns data matching its declared `returns`; the loader refuses scripts that reference navigation, form submission, input events, network or storage APIs), it is validated by the same loader as an authored one, and it is installed only through the replay gate after a mission in which it ran and its expectations passed. Scripts are never part of a non-repeatable (agreement-gate) procedure. The planner's own run-time actions stay ordinary protocol actions on snapshot rows; this amendment is about compiled playbooks only.
