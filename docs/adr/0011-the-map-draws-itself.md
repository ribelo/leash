# The map draws itself: playbooks compile from successful runs, and the site verifies them

Leash starts on a new site with no playbook; JEV drives on the fly. Every drive leaves a trace (page-kind path, each choice with its probabilities, the text typed, the outcome, the cost). When enough successful traces of one site share a path, the planner — Luna by default, at maximum reasoning — compiles them into a procedure in the playbook's language: goal steps, expectations from the checker vocabulary, args from what the text helper typed. That is a compiler over evidence, not a learner: predictable, inspectable, the same input giving the same procedure. The operator's decision of 2026-10-01: he will not review procedures; the map must draw and repair itself, with three configured states — `off`, `draft`, `auto`.

**Automatic means verified, not blind.** A compiled procedure is a *draft* until it has driven a mission successfully as a procedure — JEV choosing it, its expectations passing on the live site. In `auto`, the runner tries drafts on the next matching mission and installs the one that worked; a draft that fails is kept as evidence and retried after repair. When an installed procedure fails twice (the existing planner trigger), the planner's repair replaces it only after the repair succeeds. The gate is the site, not a human. Rejected: installing on compile (a wrong generalization would cost every future mission on that site and nobody would notice, by design); a nearest-case hint to JEV at run time (measured worse: more context lowers JEV's accuracy, 4/5 → 2/5); fine-tuning (JEV is fixed). `discover` is folded in: exploring is driving, and the draft appears on its own.

Consequences: traces persist under XDG state with bounded retention; page kinds are inferred on sites without a playbook so a trace has something to compile on; the planner gains a `continue` answer so Luna can hand control back to JEV after acting; `drive` is the command agents reach for, with a given tab kept and a created tab closed.
