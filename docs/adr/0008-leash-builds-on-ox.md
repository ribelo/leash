# Leash builds on ox, and is its first consumer

Eta v1 (a blueprint interpreter over Eio) is being replaced by ox — the eta-next line, renamed on 2026-09-29 (direct style on Eio, `result` errors, one application model; see `/home/ribelo/projects/ribelo/ocaml/ox/docs/why-ox.md`). Leash is greenfield and all operating-system seam — process supervision, pipes, a Unix socket, timers — which is exactly where v1's interpreter hurt most, so Leash becomes the first consumer of ox rather than the last consumer of v1. ADR-0001's rule stands: anything that is an effect-shaped resource or lifecycle concern without a browser concept is built in ox first, pulled by a Leash story ID. The six v1 tickets written for Leash (`etaproc`, `etarpc`, `etaipc`, `etadoor`, `etaor`, `etaso`) are superseded; their pure parts are copied when pulled. Milestone 1's specification is unchanged in behaviour and was re-cut against ox's packages (`ox`, `ox_app`, a process resource, a Unix listener, a JSON codec); the Leash flake pins the ox checkout.
